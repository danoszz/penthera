section: Security
docs: none, finding text and masking only; no flag, rule id or format changes (ai-mode.md notes the escaped-key line)

- **AI mode no longer sends most of an escaped key to the model.** A key written with `\u` escapes (`"sk-proj-…"`) was found in the decoded text, then masked in the raw text with the decoded length, so 42 of 48 characters reached the model, the Ollama cloud route included. Now a hit from the decoded text masks its whole line, and lines stay where they are.
- **Agent findings no longer print the secrets in the config they quote.** `registry-redirect` showed a token in an index URL (`https://__token__:…@pypi.corp.example`), `mcp-unpinned` and `mcp-exec` the whole launch command with its `--api-key`, `hook-exec` and `hook-pipe-shell` a `Bearer` token, and `mcp-plain-http` a basic-auth password. Every quoted command, URL and permission rule now goes through one redactor: URL userinfo, secret-named query values, the value after a secret-named flag, `NAME=value` and `Name: value` with a secret name, `Bearer`/`Basic`/`Token` credentials, `curl -u user:pass`, `mysql -p…` and every secret-scan hit are hidden. A password in an MCP server's URL is now reported as `mcp-inline-secret`, and `mcp-inline-secret` masks the way the repo scan does (a value under 20 characters shows as `***`; the old mask showed 8 of 9 characters).
- **TruffleHog evidence hides JSON-escaped secrets.** A secret with `&`, `<`, `>`, a quote or a backslash was left in the evidence bundle, because TruffleHog's JSON escapes them. The bundle now masks the parsed values and writes each line again.
- A title that quoted a secret (a permission rule, a hook script) now quotes it masked, so that finding's id changes once. If you shared a report from an earlier version, check it for these and rotate what it shows.
