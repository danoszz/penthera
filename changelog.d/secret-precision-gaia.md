section: Detection

- **A Secret Manager reference is not a secret, and a test account's password is checked first.** A real run on a Firebase app put two false positives in Act on. A value that is wholly a Google Secret Manager resource name (`projects/<project>/secrets/<name>/versions/<n>`, as Firebase Extensions write into `extensions/*.env`) is now read as a pointer and not reported. Penthera parses it: a project ID or number, a secret name that doesn't look machine-made, and a version number or `latest`. A key pasted into the name slot is still reported. A hardcoded password in a test or verify script, within three lines of an address at a test domain such as `example.com`, stays high but moves to Check first, and the finding says why. A real domain next to it, or another password in the same file, keeps it in Act on.
