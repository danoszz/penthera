section: Security

- **A file Penthera can't read fails `--repo`, `agents` and a venv scan with exit 2.** Vercel Security Review found two more places where a refused file passed in an earlier 2.3.2 build. In `penthera deps`, an installed package whose `METADATA` was over 16 MiB (or a FIFO) left the tree without a word. Now the package stays, named from its `.dist-info` folder and marked as not scanned, and a refused `RECORD` does the same. In `--repo`, a route or server file over 5 MiB was an info finding only, and nothing else read it. In `penthera agents`, an `.npmrc` or `.mcp.json` that was a FIFO, a device or over 5 MiB was skipped or an info finding. Each is still named, what was read still counts, and the run is incomplete: it exits 2, and the JSON report lists the file under `incomplete`. The MCP tools `scan_repo` and `audit_ai_tooling` carry the same `exit_code` 2. Our own sweep found the agents cases.
