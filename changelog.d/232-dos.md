section: Security

- **A repo can no longer hang `--repo`, `deps` or `agents` with a link or a FIFO.** A `package.json`, `package-lock.json`, `uv.lock`, `requirements.txt`, `index.js`, `wrangler.toml` or `route.ts` that linked to `/dev/zero` made Penthera read without end (over 2 GB of memory), and a FIFO waited forever, so a fork pull request could stall CI. The same held for `--sbom`, `node_modules/*/package.json` and a `.venv`'s `METADATA`, `RECORD` and `.pth` files. These files are now read only when they are regular files, without waiting for a writer, the project's own manifests and lockfiles only inside the project, and up to a size cap (5 MiB for source and config, 64 MiB for lockfiles). A refused file is said, by name and reason, never its content: `--repo` and `deps` report `File not read: <file>` as an info finding and go on with the rest, and `deps` then exits 2. Route discovery no longer follows a linked folder, so `routes -> /` no longer walks the disk.
- **`-r` in a requirements file reads only inside the project.** `-r /dev/stdin` waited forever, and `-r ../../etc/hosts` read a file outside the repo and could print it in an error. Now an include that points outside the project folder, or at a device or a FIFO, is not read: `deps` names the line, still checks the file's other pins, and exits 2. An include that is not there is skipped, as before.
- **A FIFO `penthera.lock` no longer hangs `penthera agents`.** It is reported as a lock that could not be read, and rug-pull detection says it is off.
- **A skill nested past 12 folders is reported, in every skill.** Only the skill you named got the high "Skill folder not read in full" finding, so a script 13 folders deep in a project skill was skipped without a word and the run could grade A. Every skill read in part now gets it, the file cap included (it was medium before). Its `penthera.lock` pin now changes when a folder past that depth appears, but what lies past it is still not pinned; the finding says so every run.
- **A download piped to a shell is found in linear time.** A file of `|sh|sh|sh...` took about 45 minutes of CPU at the 5 MB file cap. It now takes milliseconds.
- **A live check never follows a redirect to another tenant.** A redirect may move between the apex and `www.` (`example.com` to `www.example.com`, or back), or down to a subdomain of the target (`example.com` to `app.example.com`), and never to a sibling or a parent host. So `alice.vercel.app` never follows to `bob.vercel.app`, on every platform that gives each customer a host, listed or not: `hf.space`, `streamlit.app`, `notion.site` and `netlify.com` were missing from the list and still let a redirect cross. A platform's own apex (`vercel.app`) never moves into a tenant. This also stops `app.example.com` following to `api.example.com` or `example.com`; add a host you may test with `--allow-host`. The email check still reads the list of 43 platforms.
- **A FIFO `penthera.policy.json` no longer hangs `deps`, the hook or `install`.** The policy is read only as a regular file inside the project, up to 1 MiB. One that is refused gives a warning and the default policy; AI mode does not run until it can be read. The same safe read now covers instruction and registry files in `penthera agents`, an installed package's `package.json` for licenses, the source line `--giants` quotes, `penthera.suppress.json`, `.git/config` and the files `fix` and `init` read.
