section: Security

- **A repo can no longer hang `--repo`, `deps` or `agents` with a link or a FIFO.** A `package.json`, `package-lock.json`, `uv.lock`, `requirements.txt`, `index.js`, `wrangler.toml` or `route.ts` that linked to `/dev/zero` made Penthera read without end (over 2 GB of memory), and a FIFO waited forever, so a fork pull request could stall CI. The same held for `--sbom`, `node_modules/*/package.json` and a `.venv`'s `METADATA`, `RECORD` and `.pth` files. These files are now read only when they are regular files, without waiting for a writer, the project's own manifests and lockfiles only inside the project, and up to a size cap (5 MiB for source and config, 64 MiB for lockfiles). A refused file is said: `--repo` reports `File not read: <file>`, `deps` stops with an error that names the file and the reason, never its content. Route discovery no longer follows a linked folder, so `routes -> /` no longer walks the disk.
- **`-r` in a requirements file reads only inside the project.** `-r /dev/stdin` waited forever, and `-r ../../etc/hosts` read a file outside the repo and could print it in an error. Now an include that points outside the project folder, or at a device or a FIFO, stops `deps` with an error naming the line. An include that is not there is skipped, as before.
- **A FIFO `penthera.lock` no longer hangs `penthera agents`.** It is reported as a lock that could not be read, and rug-pull detection says it is off.
- **A skill nested past 12 folders is reported, in every skill.** Only the skill you named got the high "Skill folder not read in full" finding, so a script 13 folders deep in a project skill was skipped without a word and the run could grade A. Every skill read in part now gets it, the file cap included (it was medium before). Its `penthera.lock` pin now changes when a folder past that depth appears, but what lies past it is still not pinned; the finding says so every run.
- **A download piped to a shell is found in linear time.** A file of `|sh|sh|sh...` took about 45 minutes of CPU at the 5 MB file cap. It now takes milliseconds.
- **A live check never follows a redirect to another tenant of a shared platform.** On 43 platforms that give each customer a host, such as `vercel.app`, `github.io`, `herokuapp.com` and `amazonaws.com` (S3), each host is now its own site, so `one.vercel.app` is never redirected to `two.vercel.app`, which is someone else's app. Apex to `www` on your own domain still works. The list is not the Public Suffix List, so a platform it misses still counts as one site. The email check reads the same list.
