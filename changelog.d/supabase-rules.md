section: Detection

- **Supabase: a service-role key in browser code, and tables without row-level security.** A `--repo` scan now reports a service-role key (a JWT that claims `"role": "service_role"`, or an `sb_secret_` key) in a `"use client"` file or a file it imports, a Vite or Expo app's `src/`, `public/`, or under a `NEXT_PUBLIC_` or `VITE_` name, at critical. A public env name for the key, or a `next.config` `env` or `vite.config` `define` that inlines it, is high. It also reads `supabase/migrations/*.sql` in order and reports a table in `public` that no migration puts under row-level security (high), and a permissive policy for `anon` or `authenticated` that checks `true` (high to low by command). Five new rule ids, all known to `explain_finding`; a Supabase migrations line in Coverage. On the E11b dev half of CredData and 300 benign packages it reported nothing, so the secret scan's precision there is unchanged. It doesn't read the database: row-level security set only in the dashboard shows as off. See [scan.md](../docs/commands/scan.md#supabase-the-service-role-key-and-row-level-security).
